# Optional craft tools — selective external review

3 November 2026. Added at Jason's request to assess and selectively use the short-drama skill collection without overriding the Lab's experience or visual styling. Assessment and source evidence (lab file, not in kit: `reviews/SHORT-DRAMA-SKILLS-2026-11-03/ASSESSMENT.md`).

Use only the relevant section when it resolves an actual story, performance or series-continuity problem. This is an optional reference, not an installed skill, new pipeline or mandatory deliverable. Existing project direction, source approvals, directing autonomy, art-review guidance and session spending limits remain authoritative. No extra confirmation step or agent delegation is introduced.

## Scene and performance diagnosis

For a scene that feels flat, identify the character's immediate intention, the obstacle, what they try, the other's observable response and what has changed by the end. A change can be trust, understanding or shared responsibility; it need not be a confrontation or twist. Use this as a diagnostic question, not a requirement that every shot contain a reversal.

For dialogue, ask what the line attempts to do to the listener. Check whether a gesture, silence or object already conveys the information. Hide the speaker labels briefly to check whether their language remains distinguishable. Retain direct speech when it serves the character and moment. Do not add dialogue to a wordless film to satisfy a writing checklist.

Report one consequential weakness and the smallest worthwhile alternative. A valid quiet scene is not a failure because it lacks a cliffhanger. Preparation stays a synopsis and art foundation; detailed acting beats, coverage and editing belong to the director.

Craft references: [sw-dialogue](https://github.com/jtydhr88/screenwriting-skills/blob/main/plugins/screenwriting/skills/sw-dialogue/SKILL.md) and [sw-scene-craft](https://github.com/jtydhr88/screenwriting-skills/blob/main/plugins/screenwriting/skills/sw-scene-craft/SKILL.md). Selective synthesis, not adoption of their full instructions. MIT notices are in the assessment folder.

## Reference and generated-take diagnosis

Use the existing asset index and SHOT_LEDGER rather than creating a competing registry. When ambiguity actually exists, add an explicit reference role and exclusion beside the relevant input: identity/costume, world/design, layout only, material, photographic look, performance or composition. Record whether the input was actually inspected. A planned or unavailable reference cannot count as conditioning evidence.

For an observed failed take, record: expected visible/audible event; actual event and time/region; likely cause versus alternatives; proposed change; what must survive; and the result after the next authorised attempt. Evidence may be playback, sampled frames or audio; state which. Keep the liked take. Distinguish a reference mismatch, prompt ambiguity, model failure and assembly error before changing the whole look.

This mostly reinforces existing Lab practice. It does not impose additional per-shot paperwork. Never import universal frame-trim numbers, a provider's presumed capabilities, white-model conversions or a change of aspect ratio as an automatic fix. Re-rendering remains a new take with chain and sound-sync checks.

## Series continuity, only when a series is commissioned

Extend the existing series owner/bible rather than creating seven mandatory files. Keep these concepts wherever the project already owns them:

| Record | Useful information |
|---|---|
| Stable identity and world rules | Accepted identity/design; rule and limitation; exact source/approval |
| Changing state | Episode/revision; costume, injuries, possessions, location and relationship changes; causal event |
| Knowledge | What each character and the audience knows; event that reveals it |
| Setup and payoff | Stable ID; planted event; expected consequence; unresolved/developed/paid off/retired status with evidence |

Before continuing, check only relevant records for contradictions, impossible knowledge, missing causal steps and forgotten setups. Proposed events remain separate from events in an accepted script or approved finished episode. Do not infer that a planned scene happened on screen. Character growth is allowed; stable identity does not mean frozen behaviour.

Supporting reference: [ManjuForge](https://github.com/mengxiujie/ManjuForge/blob/main/SKILL.md). Use its state-tracking idea only; fixed episode milestones, numerical trust curves, mandatory captions/CTAs and platform hooks are excluded.

## Quality evidence before wider adoption

The new methods are candidate aids, not proven quality improvements. At the next suitable authorised writing task, preserve the original and compare one focused alternative for story clarity, character specificity and emotional payoff. Obtain Jason's preference through the normal review. For imagery, keep the same accepted identity/design/reference roles and compare actual output at matched scale plus motion when relevant. A prompt rewrite alone does not prove better realism.

Do not start generation merely to test this document. Do not change model/provider, palette, face family, material vocabulary, world geometry, grade or runtime based on an external preset. A proposed visual change needs an observed weakness, a reason it helps this film and normal review of its actual result.
